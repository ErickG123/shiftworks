# ADR-0007 — Sandbox output counting without goals

**Status:** ACCEPTED  
**Date:** 2026-11-18

## Context

Sandbox deliberately has no completion goals, but still needs to reuse the production simulation and show accepted deliveries per Output. The existing engine treated every accepted item without a matching goal as `NO_GOAL` rejection, which made a no-goal mode impossible to use meaningfully.

## Decision

When a layout has no goals, an Output counts an item as delivered if its `acceptedTypes` contains the item type. Wrong types remain rejected. When a layout has one or more goals, existing goal matching and `NO_GOAL` behavior remain unchanged. A goal-free simulation continues running and never enters RESULT automatically.

## Consequences

- Sandbox output counters are populated by the same `itemsDeliveredByOutput` metric and `ITEM_DELIVERED` event as campaign deliveries.
- Goal-free states do not produce `GOAL_COMPLETED` events or an automatic result.
- Tests cover correct no-goal delivery, invalid output type rejection, and the existing campaign fixtures.

## Alternatives considered

- A separate Sandbox engine would duplicate movement and rules and risk divergent behavior.
- Counting every item regardless of Output compatibility would hide routing mistakes.

## Validation

`src/game/simulation/sandbox.test.ts` runs the shared engine with blue, amber and alternating sources and covers wrong-type rejection.
